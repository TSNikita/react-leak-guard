# Глава 1: Анатомия утечек памяти в React

## 1.1. Что такое утечка памяти?

Утечка памяти (memory leak) — это ситуация, когда приложение выделяет память для объектов, но не освобождает её, когда эти объекты больше не нужны. В контексте React это означает, что компоненты, данные или функции продолжают существовать в памяти, даже после того как компонент был размонтирован (unmounted).

### Последствия утечек памяти:
- **Рост потребления RAM**: Вкладка браузера может потреблять 2GB+ памяти
- **Краш вкладки**: Браузер принудительно закрывает вкладку при исчерпании памяти
- **Деградация производительности**: GC (garbage collection) работает чаще, вызывая "фризы"
- **Потеря данных**: Пользователи теряют несохранённые данные при краше

---

## 1.2. Типичные паттерны утечек в React

### Паттерн 1: Забытый `setTimeout` / `setInterval`

```typescript
function Timer() {
  useEffect(() => {
    const id = setInterval(() => {
      setCount(c => c + 1);
    }, 1000);
    
    // ❌ Забыли return () => clearInterval(id)
  }, []);
  
  return <div>{count}</div>;
}
```

**Что происходит:**
- Компонент монтируется → создаётся интервал
- Пользователь уходит со страницы → компонент размонтируется
- Интервал продолжает работать → вызывает `setCount` → утечка

**Почему это утечка:**
- `setInterval` держит ссылку на callback
- Callback держит ссылку на `setCount`
- `setCount` держит ссылку на компонент
- Компонент не может быть удалён из памяти

---

### Паттерн 2: Незавершённый `fetch`

```typescript
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  
  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => setUser(data)); // ❌ Вызовется даже после unmount
  }, [userId]);
  
  return <div>{user?.name}</div>;
}
```

**Что происходит:**
- Компонент монтируется → начинается fetch
- Пользователь быстро уходит со страницы → компонент размонтируется
- Fetch завершается → вызывает `setUser` → ошибка "Can't perform a React state update on an unmounted component"

**Почему это утечка:**
- Promise держит ссылку на callback
- Callback держит ссылку на `setUser`
- `setUser` держит ссылку на компонент

---

### Паттерн 3: Забытый `addEventListener`

```typescript
function MouseTracker() {
  const [position, setPosition] = useState({ x: 0, y: 0 });
  
  useEffect(() => {
    const handleMouseMove = (e) => {
      setPosition({ x: e.clientX, y: e.clientY });
    };
    
    window.addEventListener('mousemove', handleMouseMove);
    
    // ❌ Забыли return () => window.removeEventListener('mousemove', handleMouseMove)
  }, []);
  
  return <div>Mouse: {position.x}, {position.y}</div>;
}
```

**Что происходит:**
- Компонент монтируется → добавляется listener
- Компонент размонтируется → listener остаётся
- Каждое движение мыши вызывает `setPosition` → утечка

---

### Паттерн 4: Замыкания (closures), удерживающие старые данные

```typescript
function DataProcessor() {
  const [data, setData] = useState(hugeArray); // 100MB
  
  useEffect(() => {
    const processData = () => {
      console.log(data.length); // ❌ Замыкание держит ссылку на data
    };
    
    const interval = setInterval(processData, 5000);
    
    return () => clearInterval(interval); // ✅ Очистка есть
    // ❌ Но processData всё равно держит ссылку на data через замыкание
  }, [data]);
  
  return <div>Processing...</div>;
}
```

**Что происходит:**
- `processData` создаёт замыкание на `data`
- Даже после `clearInterval`, замыкание может держаться в памяти
- `data` (100MB) не может быть удалён из памяти

## 1.3. Почему React Strict Mode не спасает?

React 18 в Strict Mode **двойной вызов** `useEffect` (mount → unmount → mount) в development-режиме. Это помогает найти некоторые проблемы, но:

1. **Работает только в dev-режиме**: В production Strict Mode отключён
2. **Не ловит все утечки**: Если ты забыл `return () => cleanup`, Strict Mode не поможет
3. **Постфактум**: Ты узнаешь о проблеме только после того, как она случилась

## 1.4. Реальные кейсы из production

### Кейс 1: Дашборд аналитики
**Симптом:** Вкладка крашится через 2 часа работы
**Причина:** Компонент графика обновлял данные каждые 5 секунд через `setInterval`, но не очищал его при unmount
**Результат:** 500+ интервалов в памяти → 2GB RAM → краш

### Кейс 2: Чат-приложение
**Симптом:** После 30 минут общения интерфейс начинает "тормозить"
**Причина:** Каждое сообщение создавало WebSocket-подписку, но не отписывалось при unmount
**Результат:** 1000+ открытых сокетов → деградация производительности

### Кейс 3: E-commerce корзина
**Симптом:** Пользователи жалуются, что корзина "теряет" товары
**Причина:** Компонент корзины делал fetch при каждом изменении, но не отменял предыдущие запросы
**Результат:** Гонка состояний (race conditions) → потеря данных

## 1.5. Как обнаружить утечки памяти?

### Инструмент 1: Chrome DevTools Heap Snapshots
1. Открой DevTools → Memory → Take heap snapshot
2. Сделай действие (например, открой/закрой компонент)
3. Сделай второй snapshot
4. Сравни: ищи объекты, которые не были удалены

**Минусы:**
- Требует ручного анализа
- Нужно знать, что искать
- Работает постфактум

### Инструмент 2: React DevTools Profiler
1. Открой React DevTools → Profiler
2. Запиши взаимодействие
3. Ищи компоненты, которые ре-рендерятся без причины

**Минусы:**
- Не показывает утечки памяти напрямую
- Требует интерпретации данных

### Инструмент 3: ESLint `react-hooks/exhaustive-deps`
**Плюсы:** Ловит забытые зависимости в `useEffect`
**Минусы:** Не ловит забытые `return () => cleanup`

---

## 1.6. Выводы

Утечки памяти в React — это **тихий убийца** производительности. Они:
- Накопляются незаметно
- Проявляются только в production
- Требуют ручного анализа для обнаружения
- Легко возникают из-за человеческой ошибки

**Нужно автоматическое решение**, которое:
1. Перехватывает утечки в runtime
2. Автоматически очищает ресурсы при unmount
3. Работает в production с минимальным overhead
4. Даёт диагностику для разработчиков

Именно такое решение представляет собой **react-leak-guard** — тема следующих глав.
