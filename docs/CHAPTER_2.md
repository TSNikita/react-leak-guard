# Глава 2: Существующие решения и их ограничения

## 2.1. Введение

Прежде чем представить наше решение, необходимо проанализировать существующие инструменты для борьбы с утечками памяти в React. Мы рассмотрим шесть основных подходов, используемых индустрией, и покажем, что ни один из них не решает проблему комплексно.

Это понимание пробелов в существующих решениях и привело нас к созданию `react-leak-guard`.

---

## 2.2. React Query / TanStack Query

### Что это
Популярная библиотека для управления серверным состоянием в React. Создана Tanner Linsley, более 45k stars на GitHub.

### Как работает
```typescript
import { useQuery } from '@tanstack/react-query';

function UserProfile({ userId }) {
  const { data, isLoading } = useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  });

  return <div>{data?.name}</div>;
}
```

### Что делает хорошо
- ✅ **Автоматическая отмена fetch** при unmount через `AbortController`
- ✅ Кэширование ответов
- ✅ Retry-логика, refetch на фокус
- ✅ Отличная документация

### Ограничения
- ❌ **Работает ТОЛЬКО с fetch** (не с setTimeout, addEventListener)
- ❌ Не блокирует `setState` после unmount
- ❌ Требует **полного переписывания** кода на `useQuery`
- ❌ Не даёт диагностики утечек в production
- ❌ Размер бандла: ~14 KB (gzipped) — избыточно для простых задач

### Вердикт
Отличный инструмент для серверного состояния, но **не решает проблему утечек памяти комплексно**.

## 2.3. ahooks (useUnmountedRef)

### Что это
Библиотека хуков от Alibaba. Более 13k stars на GitHub. Популярна в СНГ.

### Как работает
```typescript
import { useUnmountedRef } from 'ahooks';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const unmountedRef = useUnmountedRef();

  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (!unmountedRef.current) {  // ← Ручная проверка
          setUser(data);
        }
      });
  }, [userId]);

  return <div>{user?.name}</div>;
}
```

### Что делает хорошо
- ✅ Простой API
- ✅ Лёгкий вес
- ✅ Не требует переписывания кода

### Ограничения
- ❌ **Требует ручной проверки** `if (!unmountedRef.current)` в каждом месте
- ❌ Не отменяет fetch автоматически (нужен `AbortController` вручную)
- ❌ Не работает с setTimeout, addEventListener
- ❌ Не даёт диагностики утечек
- ❌ Только блокировка setState, не предотвращение

### Вердикт
Полезный инструмент, но **требует дисциплины от разработчика**. Человеческий фактор — главная причина утечек.

## 2.4. react-use (useUnmount)

### Что это
Коллекция хуков от Streamich. Более 4k stars на GitHub.

### Как работает
```typescript
import { useUnmount } from 'react-use';

function Timer() {
  useEffect(() => {
    const id = setInterval(() => setCount(c => c + 1), 1000);
    
    useUnmount(() => {  // ← Cleanup при unmount
      clearInterval(id);
    });
  }, []);
}
```

### Что делает хорошо
- ✅ Декларативный API для cleanup
- ✅ Работает с любыми операциями

### Ограничения
- ❌ **Требует ручного написания cleanup** для каждой операции
- ❌ Не блокирует setState после unmount
- ❌ Не даёт диагностики
- ❌ Не автоматический — нужно помнить о каждом таймере/подписке

### Вердикт
Хороший помощник, но **не автоматизирует процесс**. Разработчик всё равно должен думать о каждой операции.

## 2.5. Memlab (Meta/Facebook)

### Что это
Инструмент для обнаружения утечек памяти в React. Разработан Meta для внутренних нужд, открыт в 2022.

### Как работает
```bash
# Запуск анализа
npx memlab analyze

# Результат: список утечек с трассировкой стека
```

### Что делает хорошо
- ✅ Находит утечки **автоматически**
- ✅ Показывает точное место в коде
- ✅ Интеграция с CI/CD

### Ограничения
- ❌ Работает **только постфактум** (после того, как утечка уже случилась)
-  Требует отдельного запуска (не в runtime)
- ❌ Не предотвращает утечки, только обнаруживает
- ❌ Сложная настройка
- ❌ Не работает в production

### Вердикт
Отличный диагностический инструмент, но **не решает проблему в runtime**. Это "детектор дыр", а не "заплатка".

## 2.6. Chrome DevTools (Heap Snapshots)

### Что это
Встроенный инструмент браузера для анализа памяти.

### Как работает
1. Открой DevTools → Memory
2. Take heap snapshot
3. Сделай действие
4. Take второй snapshot
5. Сравни

### Что делает хорошо
- ✅ Полная картина потребления памяти
- ✅ Не требует установки
- ✅ Бесплатно

### Ограничения
- ❌ **Требует экспертизы** (нужно знать, что искать)
- ❌ Ручной анализ
- ❌ Работает постфактум
- ❌ Не масштабируется на команду
- ❌ Не работает в production

### Вердикт
Мощный инструмент для экспертов, но **недоступен для большинства разработчиков**.

---

## 2.7. ESLint `react-hooks/exhaustive-deps`

### Что это
Статический анализатор зависимостей хуков React.

### Как работает
```typescript
useEffect(() => {
  console.log(userId);
}, []);
// ❌ ESLint warning: React Hook useEffect has a missing dependency: 'userId'
```

### Что делает хорошо
- ✅ Ловит забытые зависимости в `useEffect`
- ✅ Работает в IDE в реальном времени
- ✅ Интегрируется в CI/CD

### Ограничения
- ❌ **Не ловит забытые `return () => cleanup`**
-  Не ловит setTimeout, addEventListener
- ❌ Не блокирует setState после unmount
- ❌ Статический анализ — не видит runtime-проблем

### Вердикт
Необходимый инструмент, но **решает только одну маленькую часть проблемы**.

## 2.9. Выявленный пробел (The Gap)

Анализ существующих решений показывает **системный пробел** в индустрии:

### Проблема 1: Фрагментарность
Нет единого решения, которое покрывает **все типы утечек**:
- fetch — решает React Query
- setTimeout — решает react-use
- setState после unmount — решает ahooks (вручную)
- addEventListener — решает react-use (вручную)

**Разработчик должен комбинировать 3-4 библиотеки**, чтобы получить полную защиту.

### Проблема 2: Ручной труд
Большинство решений требуют **ручного написания кода**:
- `if (!unmountedRef.current)` в каждом месте
- `return () => cleanup` для каждой операции
- Ручной анализ heap snapshots

**Человеческий фактор — главная причина утечек.** Пока решение требует ручной работы, проблема не решена.

### Проблема 3: Отложенная диагностика
Существующие инструменты (Memlab, DevTools) работают **постфактум**:
- Утечка уже случилась
- Пользователь уже пострадал
- Нужно тратить время на анализ

**Нет runtime-защиты**, которая предотвращает утечки до того, как они произойдут.

### Проблема 4: Production-слепота
Большинство инструментов работают только в development:
- React Strict Mode — только dev
- ESLint — только dev
- Memlab — только offline

**В production разработчик слеп** к утечкам памяти.

---

## 2.10. Выводы

Существующие решения — это **набор инструментов**, а не **система**. Они решают отдельные части проблемы, но не проблему целиком.

**Индустрии нужно решение, которое:**
1. ✅ Покрывает **все типы утечек** (fetch, timers, events, setState)
2. ✅ Работает **автоматически** (без ручного кода)
3. ✅ Предотвращает утечки в **runtime** (не постфактум)
4. ✅ Работает в **production** с минимальным overhead
5. ✅ Даёт **диагностику** для разработчиков

Именно такое решение представляет собой **react-leak-guard**, архитектура которого описана в следующей главе.
